For each new piece of software, once the user has described what they want, begin with a mockup of the screens; the code follows once the mockup is agreed.

**Why:** the user's own words (2026-10-06): it frames the rest of the work and speeds it up. They describe it as their recurring method.

**How to apply:** when asked for a new app (or a substantial new window), produce the mockup first and wait for the user's reaction before implementing, unless they say to skip it.

The same held for a physical product (2026-10-08, the Onyx Pi 4 case): a full CAD model of an aluminium slab, built without showing concepts first, was rejected at first sight ("looks like an internet box, not a computer"; the user wanted wood, e.g. walnut). My reading: for any design work, show a few quick concept pictures and let the user pick before detailing.
